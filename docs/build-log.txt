§1  WHAT THE PRODUCT IS
================================================================================
Real-time multimodal edge AI for construction-site safety, spatial compliance
and automated reporting. Source spec: "Product Requirements Document (PRD)_
FieldPilot AI.md". Living plan: plan.md. Status board: tracking.md.

Target hardware is Ray-Ban Meta smart glasses (no display — alerts are audio
earcons + speech + haptics) with a phone as the compute gateway. That hardware
is NOT present, so the system currently runs on a webcam or a browser camera.

The one architectural rule, from plan.md:
    AI models NEVER call notification/dashboard APIs directly.
    Model -> Event -> Trigger Engine -> Rules Engine -> Notification -> Dashboard
Everything observable flows through that chain. Violating it is a design break,
not a style preference.

Safety posture is ADVISORY, not authoritative. Fail-safe on model/stream
failure. This matters repeatedly in §6 and §7.

§6  BUGS FOUND AND FIXED — read before touching related code
================================================================================
All of 1-7 were PRE-EXISTING. 9-10 were introduced during this session's work
and caught before commit.

1. events/schema.py — dedup_key() ignored element/ppe_item/defect even though
   its own docstring promised them. Effect: two unrelated issues in the same
   zone collapsed into ONE alert and the second never reached the rules engine.
   Fix: fallback chain dedup_key -> subject -> element -> ppe_item -> defect.

2. perspective.py — the bearing to a hazard was computed with a 1-pixel focal
   length, saturating to +-90 degrees for any offset. Fix: proper camera-ray
   difference using the real focal length.

3. perspective.py — OpenCV 5's SOLVEPNP_ITERATIVE refuses <6 points without an
   extrinsic guess. Fix: seed a frontal rvec + estimated tz so 4/5-point face
   fits work; SQPNP as graceful retry.

4. offline/outbox.py — coerced timestamps with float(), which CRASHES on the
   ISO-8601 string that Event.model_dump_json_safe() actually emits. The edge's
   forwarding path would have failed on its very first event. Fix: as_epoch()
   accepting float | int | ISO-8601 | datetime.

5. feedback/service.py — defaulted a sample's label to the event FAMILY ("ppe"),
   which never matches a YOLO class name, so every approval without an explicit
   label was silently discarded by the dataset builder -> zero training signal.
   Fix: read the detector's own class from payload["class"]; leave None and skip
   VISIBLY when unresolvable.

6. broadcast/hub.py — a device connecting WITHOUT a zone received every zone's
   advisories, exactly the site-wide noise PRD 4.4 exists to prevent. Fix:
   only dashboards may span zones.

7. Assorted: PPEChecker swallowed load failures silently; zones.update skipped
   the name validation create performs; docstore could not enforce immutability
   for undeclared columns (now a startup error, not silent data loss);
   ingest.chunk_text could append an empty chunk.

8. backend/service.py — THE LLM GATE SUPPRESSED REAL HAZARDS. See §5 22:00 and
   §7 item 3. Fix: no vision -> no veto; severity ceiling; rejections above the
   line persist as llm_verdict.disputed and still escalate.

9. safety/ppe.py — set_tracked_items resolved a payload of all-unrecognised
   names to the EMPTY SET, silently disabling EVERY PPE check. The most
   dangerous possible reading of "I could not understand you". Fix: keep the
   current selection unless the all-off request is explicit (an all-False
   mapping or an empty collection still works).

10. backend/app.py — /models/select wrapped the registry's COROUTINE
    ensure_weights in run_in_threadpool, yielding an un-awaited coroutine that
    stringifies into a bogus "weights" path instead of downloading anything.
    The first test missed it by only covering download=False. Fix: await
    directly; added tests over the download and failure paths.

§7  DESIGN DECISIONS AND RATIONALE
================================================================================
1. ONE record store over two backends (storage/docstore.py). Declared columns
   stay SQL-queryable; undeclared keys ride in a JSON payload column. Adding a
   domain table costs a declaration, not two repository classes. The older
   explicit repositories in backend/store.py and events/store.py predate it and
   were left alone rather than churned.

2. RFI citations come from chunk METADATA, never from LLM output, and retrieval
   is server-side must-filtered by zone. A hallucinated clause number therefore
   cannot reach the document, and a clause from another zone cannot be cited.
   Measured numbers are also stated deterministically ABOVE the LLM prose,
   because llama3.2:3b was observed calling a 7.5 mm deviation "within +-5 mm".

3. The LLM is NOISE CONTROL, not a safety authority. Two hard guards:
   (a) no vision -> it may annotate but never suppress;
   (b) even with vision it cannot suppress above llm.suppress_max_severity
       (default medium).
   Rejections above the line persist as llm_verdict.disputed and still reach
   people. Rationale is empirical, not theoretical — see §6 item 8. Fail-open
   on infra failure was already correct and was kept.

4. The learning gate MEASURES and REPORTS. plan.md explicitly rejects
   "guaranteed mAP gain" framing. A regression is recorded as a completed run
   with promoted:false. Training validates on the LOCKED val set that no
   feedback can contaminate. A run refuses to start without a populated val set
   rather than inventing one.

5. Browser ingest is a CAMERA SOURCE, not a parallel system. Browser frames go
   through the same pipeline and their hazards onto the same bus, tagged
   ingest="browser" for provenance. Anything else would create two universes
   with divergent alerting.

6. Devices vs dashboards on the WebSocket. Dashboards are the supervisory view
   and see every zone unless pinned. Devices are strictly zone-scoped and
   receive only the downgraded advisory — never the full alert stream, never
   dashboard notifications.

7. Alert acknowledgement maps onto the EXISTING lifecycle (resolve) rather than
   adding hrm's separate boolean, which could disagree with `state`.

8. Operator settings persist and OVERRIDE config.yaml, so a restart does not
   silently revert a site's configuration. They reach the live edge over
   control.settings, mirroring the existing control.inspection pattern.

9. Real PPE weights: agent B searched Hugging Face, checked licences, and
   actually downloaded and loaded 3 candidates before wiring
   Hansung-Cho/yolov8-ppe-detection, whose 10 classes match exactly what this
   codebase was written against. The registry pins immutable git revisions
   (never /resolve/main/) plus SHA-256; all 5 PPE digests were re-verified
   against upstream LFS metadata.

10. Honesty over appearance: where something could not be obtained or proven,
    the code and docs say so. structural_damage_best.pt has no public source —
    fetch_models.py prints instructions and exits non-zero for that model
    rather than inventing a URL. The lexical embedding fallback reports itself
    as non-semantic. The demo val set is watermarked and README'd as fake.

§8  DELIBERATELY NOT BUILT
================================================================================
Deferred by explicit user decision (edge/wearable hardware not available).
Marked not-started in tracking.md rather than stubbed or faked:
  * LiveKit / WebRTC ingest (M2.1) — deps declared, no code. Browser ingest

  * Battery-drain harness (PRD success criterion) — needs the device.
  * Ray-Ban Meta glasses integration itself.

Other honest gaps:
  * Cloud TTS + haptics: code paths exist for ElevenLabs/Google and a mobile
    endpoint, but no keys and no device are wired, so local espeak + logged
    "simulated buzz" is what actually runs.
  * structural_damage_best.pt cannot be re-fetched on a clean clone.
  * The demo val set is synthetic. Its mAP50 numbers are mechanically real but
    semantically meaningless — replace with labelled site frames before
    trusting any delta.
  * data/blueprints/* is gitignored, so the demo spec corpus does not reach a
    fresh clone.
  * possibilities.md items needing new models or depth/SLAM sensors remain out
    of scope (see docs/possibilities-coverage.md).

§10  GOTCHAS FOR WHOEVER WORKS ON THIS NEXT
================================================================================
* Do NOT let a model call a notification/dashboard API directly. Publish an
  event. The chain in §1 is the architecture.

* config.yaml env overrides are FIELDPILOT_<SECTION>__<KEY>, double underscore
  for nesting. They work and are used by run_all.sh to select postgres/redis.

* Producers should set payload["dedup_key"]. Without it the fallback chain in
  events/schema.py picks element/ppe_item/defect. If you add an event family,
  give it a discriminator or unrelated issues will merge.

* The trigger engine only runs rules for outcome "created"/"reactivated". A
  repeated detection MERGES and returns early — so a second event with the same
  dedup key will NOT fire rules. This surprised me twice during testing; if a
  rule "does not fire", check for an existing ACTIVE alert first.

* Seed rule thresholds matter when testing: rebar-deviation-rfi needs
  deviation_mm > 20, severe-crack needs severity_score > 0.85.

* docstore put() is a full REPLACE (absent columns become NULL); patch() merges.
  spec.immutable only works for DECLARED columns — start() now raises if you
  list an undeclared one.

* TestClient websocket receive_json() BLOCKS FOREVER if nothing arrives, which
  hangs CI instead of failing. Use the threaded _recv helper pattern in
  tests/test_backend_platform_api.py or tests/test_browser_camera.py.

* Next.js rewrites do NOT proxy WebSockets. WS clients connect directly to

  NEXT_PUBLIC_FIELDPILOT_EDGE_WS overrides.

* frontend/AGENTS.md is real: this Next.js version differs from most training
  data. Read node_modules/next/dist/docs/ before writing frontend code. The
  eslint rule react-hooks/set-state-in-effect will reject setState in an

  the LLM on top causes verifier TIMEOUTS under load (they fail open, which is

  parent shell dies, the WHOLE STACK including infra goes down. Launch it with
  setsid/nohup if you need it to outlive your session.

* Weights are gitignored (models/*.pt and /*.pt at the root, because

* npm run format:check was already failing on pre-existing files before this
