**1\. Product Overview** FieldPilot AI is a real-time, multimodal artificial intelligence system deployed on constrained edge hardware. The product is designed to enhance construction site safety, verify spatial compliance, and automate administrative reporting through a zero-hallucination, feedback-driven platform.  
**2\. Target Audience & Hardware Profile**

* **Target Users:** Construction site workers, safety inspectors, and site engineers.  
* **Primary Hardware:** Ray-Ban Meta Wayfarer Gen 2 smart glasses, equipped with a 12-megapixel sensor streaming 3K resolution video at 30 frames per second.1  
* **Hardware Constraints:** The wearable hardware completely lacks a visual display. All systemic alerts and user feedback must be delivered exclusively via auditory channels (earcons and voice) and haptic feedback routed through a paired mobile device acting as the computational edge gateway.1

**3\. Core Objectives**

* Deliver real-time detection of physical hazards and verify cognitive recognition of those hazards by the worker.  
* Automate spatial measurement-versus-specification checks to reduce administrative bottlenecks.  
* Draft Requests for Information (RFIs) automatically, citing precise architectural blueprints.1  
* Establish a closed-loop system where supervisor feedback (approvals/rejections) directly and measurably improves model accuracy.1

**4\. Feature Specifications**

* **4.1 Baseline Safety Tier (Edge Execution)**  
  * **Object & Pose Detection:** Real-time identification of workers and Personal Protective Equipment (PPE) using YOLOv8-Pose to extract 17 anatomical keypoints (e.g., nose, eyes, ears, shoulders).2  
  * **Persistent Tracking:** Multi-object tracking integration (BoT-SORT) to maintain consistent worker IDs, even during temporary visual occlusions.3  
  * **Fall Detection:** Kinematic analysis of upper torso displacement versus lower extremity keypoints to confidently differentiate rapid, non-linear falls from standard bending or kneeling movements.1  
  * **Attention Tracking:** Head-yaw gaze estimation mapped against a mathematical 3D projection. Implements a Passive ![][image1] Unnoticed ![][image1] Escalated state machine utilizing a strict dwell-versus-glance temporal threshold to ensure genuine cognitive engagement with a hazard.1  
* **4.2 Differentiated Compliance Tier (Cloud Execution)**  
  * **Measurement & Scale Calibration:** Spatial calibration utilizing a known physical reference object to calculate precise pixel-to-millimeter ratios, allowing the system to calculate exact real-world distances.5  
  * **Specification Verification (RAG):** Context-aware blueprint question answering utilizing a Qdrant vector database. Relies on strict Boolean payload filtering (e.g., exact matching of project IDs and zone metadata) to prevent cross-zone hallucinations when retrieving architectural specs.6  
  * **Automated RFI Drafting:** Triggers the automatic generation of an RFI document when a spatial deviation (e.g., incorrect rebar spacing) is detected, citing the relevant clause from the ingested PDF corpus.1  
* **4.3 Multimodal User Interface (Display-less)**  
  * **Earcons:** Short, category-specific audio patterns that condition the user to subconsciously recognize hazard types before a verbal explanation finishes.1  
  * **Text-to-Speech (TTS):** Low-latency verbal alerts processed using a highly optimized, quantized version of Faster-Whisper on the edge device.7  
  * **Haptic Dispatch:** Severity-scaled vibration patterns pushed to the user's paired mobile device.1  
* **4.4 Cross-Worker Broadcast**  
  * A spatial zoning feature that issues lower-priority, secondary hazard advisories exclusively to other connected workers operating within the identical geographic zone as the primary detector.1  
* **4.5 Offline Store-and-Forward**  
  * A localized SQLite caching queue designed to capture safety events during network or Wi-Fi dropouts. The system must seamlessly flush the queue back to the central API with reconciled timestamps once connectivity is restored.1

**5\. Technical Architecture**

* **Video/Audio Proxy:** Low-latency WebRTC routing utilizing LiveKit Agents to securely bridge the wearable hardware, the mobile edge phone, and the cloud backend.8  
* **Inference Quantization:** YOLO models aggressively quantized to LiteRT formats. Weights are compressed to INT8 for storage but process in FP32 precision during tensor operations to retain high accuracy on bounding box coordinates.10  
* **Infrastructure:** A modular FastAPI backend relying on PostgreSQL for relational zone data, Redis for publish/subscribe event brokering, and Qdrant for dense semantic embeddings.1

**6\. Success Criteria & Validation Metrics**

* **Latency:** The median end-to-end response time (Hazard detection to Auditory/Haptic Alert) must remain strictly under 500ms for critical events.1  
* **Accuracy Delta:** The system must demonstrate a non-zero, mathematically documented improvement in mAP50 scores on a locked, immutable validation dataset after processing human feedback in the learning loop.1  
* **Offline Reliability:** Simulated mid-run network terminations must result in zero dropped events upon reconnection.1  
* **Power Efficiency:** Battery drain rates must be recorded during a continuous one-hour active field test and prove proportional to the hardware's rated 8-hour operational life.1

**7\. Implementation Phases & AI Generation Prompts**  
To ensure precise execution, the following paragraphic prompts are designed to be fed sequentially into an autonomous coding agent to build the system phase by phase.

* **7.1 Phase 0: Foundation and Tier 1 Prototyping (Days 1–5)**Act as an expert Principal Systems Architect and generate the complete Phase 0 Python backend and machine learning pipeline for a real-time construction safety application. Begin by generating a comprehensive docker-compose.yaml file that provisions PostgreSQL, Redis, and Qdrant containers, explicitly avoiding Kubernetes to streamline the initial MVP deployment. Next, generate a structured FastAPI backend application utilizing Pydantic models for strict data validation, featuring a robust modular directory structure including explicitly named folders for core, safety, compliance, alerts, reasoning, learning, display, logging\_, tests, data, models, and docs. Implement a global, version-controlled config.yaml file that dictates all tunable parameters, including gaze dwell time thresholds, tracking match thresholds, alert cooldowns, and bounding box confidence minimums. Generate the core computer vision script using the Ultralytics Python API, instantiating a YOLOv8-pose model to extract 17 anatomical keypoints from a mock webcam video stream. Integrate the BoT-SORT tracker directly into the YOLO predict pipeline by utilizing the stream=True and persist=True arguments to ensure stable ID assignment across occlusions, and expose the track\_buffer and match\_thresh parameters to allow for tuning against ID flickering. Following this, generate a fall detection heuristic class that processes the YOLOv8 keypoint outputs, calculating the vertical displacement velocity of the shoulder, hip, and ankle indices over a rolling frame buffer to accurately distinguish rapid, non-linear falls from normal kneeling or bending movements. Simultaneously, implement an attention tracking state machine class that processes spatial gaze vectors to determine if a worker is actively looking at a detected hazard. The state machine must instantiate a rigid dwell-versus-glance logic, requiring a contiguous gaze hold of at least 600 milliseconds on the bounding box coordinates before transitioning the internal tracking state from Passive to Unnoticed, and eventually to Escalated. Finally, generate a mock edge device audio loop using the Faster-Whisper library optimized with the CTranslate2 engine, specifying the model size as medium and the compute\_type as int8, simulating a transcription pipeline that feeds into a basic text-to-speech alert function, and wrap the entire pipeline into an asynchronous Python event loop designed to execute flawlessly for a simulated ten-minute validation run.  
* **7.2 Phase 1: Hardware Integration and Real-World Calibration (Days 6–10)**Act as a Principal Edge Hardware Engineer and generate the complete Phase 1 integration logic for routing live video and audio streams from wearable hardware into a distributed cloud-edge processing pipeline. Begin by writing an asynchronous Python integration using the LiveKit SDK to establish a secure WebRTC proxy session, capturing the live video and audio tracks from the connected Meta Wayfarer device. Implement an adaptive frame sampling mechanism within the LiveKit AgentSession that processes incoming video feeds, resizes them to optimal 1024x1024 dimensions, converts the BGR frames to RGBA format, and queues them for inference without blocking the main asynchronous event loop. Next, generate a highly optimized edge deployment inference script that loads a LiteRT dynamically quantized YOLOv8 TFLite model, explicitly coding the inference pipeline to acknowledge that while the weights are loaded as INT8 for memory compression, the internal inference tensor operations process in FP32 to maintain high precision for bounding box coordinate outputs. Develop an OpenCV calibration and measurement module that accepts an image frame, identifies a known rectangular reference object utilizing contour detection and minimum area bounding rectangles, calculates the precise pixel-per-millimeter ratio, and uses this mathematical ratio to compute the exact Euclidean distance across an identified construction anomaly. Following this, generate the auditory and haptic user interface pipeline tailored specifically for display-less hardware, creating an audio dispatch controller that instantly plays distinct categorical earcon sound files based on the detected hazard type, immediately followed by an asynchronous TTS string, synchronized with a command payload sent to the mobile device to trigger severity-scaled haptic vibrations. Finally, implement a head pose estimation algorithm using cv2.solvePnP, processing the 2D facial landmarks extracted by the pose model against a generic 3D human head model matrix to extract the rotation and translation vectors. Convert the resulting rotation vector into a rotation matrix via the Rodrigues algorithm, decompose it into Euler angles representing the precise yaw, pitch, and roll in radians, and feed this multidimensional gaze vector into the previously established attention state machine to verify hazard recognition.  
* **7.3 Phase 2: Hardening, Learning Loops, and Scale (Days 11–15)**Act as a Senior Backend Data Architect and generate the Phase 2 production hardening, fine-tuning pipeline, and advanced vector search logic for a scalable edge AI system. Begin by implementing a continuous feedback logging mechanism in FastAPI that captures user approval and rejection events from the frontend dashboard, serializing these boolean interactions alongside the original image frame and bounding box coordinates into a dedicated PostgreSQL table for supervised fine-tuning. Write a Python automation script that extracts these validated records, formats them into a standard YOLO-compatible dataset structure, executes a fine-tuning training loop on the base weights, and subsequently evaluates the newly generated weights against a locked, immutable validation dataset, automatically logging the delta in the mAP50 metric to prove system improvement. Next, generate the advanced Retrieval-Augmented Generation pipeline utilizing the official Qdrant Python client and Langchain integration. Implement a highly specific vector search function that uses the query\_points method, enforcing strict semantic retrieval boundaries by constructing a query\_filter utilizing the Filter object. Within this filter, define a must array containing multiple FieldCondition objects that utilize MatchValue to enforce exact matches on metadata payloads such as project ID, zone location, and document category, ensuring the LLM is only provided context from the strictly relevant architectural specifications and preventing cross-zone hallucinations. Following this, construct a cross-worker hazard broadcast service using Redis pub/sub, which listens for critical hazard events emitted by a primary device, checks the active spatial zone of all other connected WebSocket clients, and selectively pushes a serialized lower-priority advisory alert only to the devices operating within the identical geographic zone. Finally, write an offline store-and-forward queue mechanism that detects WebSocket disconnections, writes all hazard and inference events to a local SQLite cache on the edge device, and seamlessly flushes the event queue back to the central backend API with proper timestamp reconciliation once the network connection is restored.
